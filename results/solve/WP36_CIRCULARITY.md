# WP36 — The circular-inference audit: five results that were conclusions from their own premises

    python scripts/solve/wp36_circularity.py
    -> results/solve/wp36_circularity.csv
    -> results/solve/wp36_circularity.json

    python scripts/solve/wp36_circularity.py --self-test

## Why this exists

"Fix them all" needs a definition of *them*. Correcting individual numbers does
not stop the next one, so this work package names the **error class** that
produced the last four failures and turns each instance into a check that fails
if it comes back.

The class is **circular inference**: a quantity is computed from a construction
that already contains the conclusion, then reported as if it were evidence. It is
not arithmetic error and it is not dishonesty, which is exactly why it survived
review four times. Every instance below passes every arithmetic check, because
the arithmetic is fine. What is wrong is the claim attached to it.

The audit is mechanical on purpose: each of the five has a **predicate** that is
true of the circular construction and false of a genuine one, so the repository
can be tested for this class rather than being trusted about it.

C3 and C4 are earlier instances of the same class, recorded here so the class is
complete rather than a description of the most recent bug.

### C1 — the 48 nt "agreement" (the one I published most loudly)

With `a = s^(−1/n) − 1` and `s = 2^(−1/R½)`:

```
1 + a = 2^(1/(n·R½))     ⇒     δ* = 1/log₂(1+a) = n · R½
```

`δ*` **is** the median product length in nucleotides. So "M5 derives 47.98 bp and
L&C observed 48 nt" compares `6 × 8` with `8 × 6`. It is a tautology.

The predicate that exposes it: the identity holds for **every** `n`. Sweeping
`n = 1…24` leaves `δ*` proportional to `n` while the fold `κ` moves only
**7.52 %** — so `δ*` is set entirely by the median length you put in, and `κ` is
the only quantity carrying information. WP34 scored "M5 derives the observed
48 nt exactly" at **90 %**; that entire 90 % was evidence-free, and it was the
largest single term in `P(M5)`.

### C2 — the 88 % (already retracted by WP35, recorded here)

`(s₀−φ₀)/s₀` is a function of the two quantities whose mismatch *is* the anomaly
M5 exists to explain, so it cannot explain it. The predicate: it is **negative**
in the +PT arm (−0.0796), and a fraction of a population cannot be negative.
WP34 compared it to `1 − 2.73/4.00 = 0.318` — itself not a physical
probability — and stopped.

### C3, C4 — the earlier pair

Recorded, not re-litigated: a "confirmation" whose expected value came from the
null it was testing, and a loop-ablation whose detector and remover shared a
definition. Both share the signature: **the check uses the thing it is checking.**

### C5 — "physical" benchmarks

`data/benchmarks/*.csv` are generated by `np.random.seed(42)` from chosen
`k_on`, `k_off`, `R_max`. The analysis pipelines recover those parameters to
within noise, which was described as validating the pipeline against **physical**
data. The predicate: exact parameter recovery is what you get when you write the
answer in. Relabelled **SYNTHETIC** at source (generator docstring, freeze
manifest, the two tests, the freeze doc).

### C6 — there is no out-of-sample test on a second enzyme

WP22 presents a table headed *"M5 passes an out-of-sample test"*, with Wang 2007
as a second, independent enzyme:

| system | a₀ | a₁ | predicted fold | measured |
|---|---|---|---|---|
| Wang 2007 | 0.15964 | 0.03563 | **4.48×** | **not measured** |

The last column says it. `4.48×` is `a₀/a₁` computed **from Wang's own two R½
values**, so pushing it back through the identity returns Wang's input to
**2 × 10⁻¹⁵**. It is an identity wearing the word "prediction".

Consequence: the **only measured off-rate fold in this programme is L&C's ≥4×** —
the very datum M5 was built on. `s = (1+a)⁻⁶` has **never been tested on a second
enzyme**. WP34's `0.60` for "survives an independent enzyme" was scored as though
it had.

### C7 — δ\* is a statement about `n`, not about the enzyme

`δ* = 1/log₂(1 + a₀/κ)` with `a₀ = s₀^(−1/n) − 1`. **Hold the fold fixed at
3.267 and vary only the assumed exponent:**

| n | δ\* (bp/PD) | gate vs 50 |
|---|---|---|
| 1 | 8.93 | closed |
| 2 | 18.59 | closed |
| 3 | 28.27 | closed |
| 4 | 37.94 | closed |
| **6** | **57.30** | **OPEN** |
| 8 | 76.66 | OPEN |
| 12 | 115.38 | OPEN |
| 24 | 231.54 | OPEN |

The fold is identical in every row. `δ*` runs **8.9 → 231 bp/PD (26×)** on the
exponent alone. And `n` and `τ` are **confounded** — several `(n, τ)` pairs give
the same 3.267 fold — so a measured fold cannot fix both, and **nothing in this
repository measures `n`**.

So the maintenance gate does not test the maintenance hypothesis. It tests which
exponent you assumed. `n = 6` is a reasonable choice (one escape opportunity per
incorporated nucleotide... of which there are 6 per repeat), but it is a *choice*,
and the gate's OPEN/CLOSED status flips between `n = 4` and `n = 6`.

## What the audit adds mechanically

For each instance the CSV records `claim`, `actual`, `predicate`, `holds_for`,
`status`. `--self-test` then checks:

1. **C1 for all n** — `δ* = n·R½` to 1e-9 across `n = 1…24`, and `κ` spread over
   that range under 10 %;
2. **C1 is evidence-free** — the same 48 nt would be "derived" for any `n`, so
   the claim cannot distinguish models; asserted by constructing `n = 1` and
   `n = 24` and showing both "predict" their own median length;
3. **C2 is negative in +PT** — the predicate, not the story;
4. **C5 recovers its own parameters** — refitting the synthetic fixture returns
   the inputs, demonstrating the circularity rather than describing it;
5. **the retractions are present** — every document that carried a refuted claim
   carries its marker, checked against the files;
6. **C6** — Wang's "prediction" recovers its own input to `1e-9`, and WP22's own
   table still records Wang as *not measured*;
7. **C7** — `δ*` at a **fixed** fold varies >20× with `n`, `n = 1` and `n = 24`
   straddle the 50 bp/PD gate, and `n`/`τ` are confounded.
